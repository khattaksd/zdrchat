# Common Operations

## Models

The model list is **fetched live from OpenRouter** — there is no hardcoded catalog to edit. To change how models appear:

- **Dedup / family selection** → `src/lib/api/dedup.ts` → `deduplicateModels()` and `baseFamily()` (how date-suffixed variants collapse).
- **Grouping buckets** (`flagship` / `fast` / `specialized` / `all`) → `dedup.ts` → `groupByFamily()`/`getPriceNum()` and the `ModelGroup` type, consumed by `ModelPicker.svelte`.
- **Popular defaults** → `OpenRouterClient.fetchPopularModels()` (daily rankings), stored in `settings.popularModelIds`.

No API-client changes are needed for new models — OpenRouter routes them automatically.

## Add / change a theme

1. `src/app.css` — add/extend a `[data-theme="<name>"]` block of CSS custom properties (dark is the default; existing: light, sepia, nord, catppuccin, tokyo-night).
2. `src/lib/store/settings.svelte.ts` — register the theme id/name in the theme list used by `SettingsPanel.svelte`.
3. `App.svelte` applies `data-theme` on `<html>` dynamically — no further wiring needed.

## Density modes

Defined in `src/app.css` via `[data-density="tight"|"cozy"|"sparse"]` spacing variables. Adjust the variables, keep the option list in `settings.svelte.ts` in sync. `App.svelte` applies `data-density` on `<html>`.

## PWA / service worker

- Config lives in `vite.config.ts` → `VitePWA({...})` (autoUpdate; manifest; icons from `public/icons.svg`).
- The service worker is **auto-generated by Workbox** — do not hand-write SW logic.
- `__BUILD_TIME__` is injected via `define` in `vite.config.ts`.
- Icons/assets live in `public/`.

## Keyboard shortcuts

Handled in `src/App.svelte` (`handleKeydown`). Current: `Enter` sends (Shift+Enter newline), `Escape` closes panels / stops streaming, `Ctrl/Cmd+K` model picker, `Ctrl/Cmd+,` settings.

## Add component-local vs shared state

- **Component-local** → Svelte 5 `$state()` inside the `.svelte` file (see `inputText`, `showSettings` in `App.svelte`).
- **Shared across components** → add fields to the existing rune objects in `store/*.svelte.ts` (chat/settings/status). Group by feature; don't create a new store file per concern.
- **Persisted** values → read/write through `lib/db/dexie.ts` `getSetting`/`setSetting` (e.g. `App.svelte`'s `onMount` load + setters).
